# First-person 3D slice — 2026-11-18

Branch: `codex/3d-first-person-slice`. This report accompanies the implementation commit.
Status: first playable for operator review, not full v22 parity or a finished art pass.

## Play

- Windows: `../.build/3d/windows/RockBottom.exe`, standalone with embedded data.
- Browser: `http://127.0.0.1:8073/` while the local server is running. Restart with
  `python -m http.server 8073 --bind 127.0.0.1 --directory .build/3d/web` from the repo root.
- [Build instructions and controls](../game3d/README.md).
- [Block](../artifacts/3d-slice/block.png), [title](../artifacts/3d-slice/title.png),
  [Tony](../artifacts/3d-slice/tony.png), [Pete](../artifacts/3d-slice/pete.png),
  [Lurch](../artifacts/3d-slice/lurch.png).

The original root browser entry, `src/`, frozen v19 and all existing gate definitions are unchanged.
The new slice contains the Block, Tony, Pete, Yuri, Lurch, Brutus, the possum, bounded finds,
trading, melee, the high/crash loop, death recovery, native saving and an async browser adapter.
The subset economy and omitted systems are explicit in [the spec](../SPEC-3D-SLICE.md).

The native tour drives production callbacks and actual physics frames through a real 18-second
high and 8-second crash, then saves/reads a separate QA file. Scene integration covers melee,
Lurch defeat, wall obstruction, modal pause, death and reload. This is engine-driven evidence,
not a completed human-controlled playthrough. Final native eye-level captures were inspected;
the reopened-menu placement bug was fixed and its logical viewport bounds are checked.

The packaged Windows executable boots headlessly and exits cleanly. Web shell syntax checks
and export pass; the served HTML returns HTTP 200. Computer Use stopped because it could not
reliably determine the active Windows browser URL. Browser pointer capture, audio and IndexedDB
round-trip remain unverified in the browser UI; no alternative UI automation bypassed the stop.

Rendering capture: 1280x720, NVIDIA GeForce RTX 3080, Compatibility/OpenGL3.3, six NPCs.
Hidden-window diagnostics reported mean frame interval 2.30ms, p95 3.55ms, CPU process 84.11ms
and 2,625 draw calls. These inconsistent timing measures are not a foreground FPS benchmark.
The 60+ NPC / under-16ms target is **unverified**; mesh batching and a representative foreground
stress profile remain required before scaling the neighborhood.
