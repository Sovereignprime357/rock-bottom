# Full 3D port: live-system inventory and architecture audit

2026-11-18. Planning/audit artifact, not a port completion report. Baseline inspected: `c9d61d2` (`Refine 3D characters, storefronts, and street materials`). VIBE was read first. This packet made no gameplay edits and ran no Godot instance. The only runtime inspection was a read-only census through the existing Node VM harness, after `startGame(false)`; it exited 0. No gate suite was rerun for this audit.

The target is the active **v22** modular game, including its earlier shipped systems and later amendments. Frozen v19 is a behavioral reference for retained behavior, not the entire port inventory. Existing `game3d/` is a useful first-person/renderer/input/export foundation, but its explicitly reduced slice is not a full-game model. Every row below remains a port obligation unless a later explicit spec decision changes it.

## Save boundary and recovery obligations

The live 2D key is `rockbottom_save_v8`, containing payload **version10**; loader accepts version≥8. The existing 3D namespace is `rockbottom_3d_slice_v1`, **schema1**, with a much smaller unrelated shape. Neither the key suffix nor the scene version is the full model schema.

The full durable model needs:

- Player placement, HP/resources/shakes/cred/brain/wanted/rank, inventory/lifetime, Tony offenses, equipment/cart/weapon, Brutus defeats, Stripe loyalty, soap rocks, hitters/high-kind flag and faction values.
- Permanent NPC deaths with transient/guard/pretender exclusions; collected pile IDs; achievements; counters; quests; hustles and snapshots; route cursor/stops/serial; office upgrades/jobs/day caps; district claims; kingdom stage/marks/defeats/daily pretender state.
- Day/time/weather; looted dumpster identity; vendor-met set; behavioral flags including tool locker, ownership, once-per-save events and discoveries; crown pickup; phone count; shared hideout stash; recognition; concession clocks; graffiti/poster layout or an explicitly migrated 3D equivalent.

High/crash timers are **not written** by 2D save; a fresh-page load starts with initialized zero timers. Stun/slow reset explicitly. Active kingdom fights demote to retry state while paid progress witnesses reconcile upwards; live boss/incident objects do not serialize. A mid-session load is not necessarily the same as fresh-page initialization; give the 3D codec an explicit transient-reset contract. Generic fields in `runtime` are not automatically durable.

Use stable prop IDs instead of copying `"x,y"` dumpster keys into metres. Any optional legacy import must map these keys and placement via a known world version and must never overwrite the original save. Full game state in a new 3D schema and migration from the published slice should be specified; cross-import from 2D is a separate explicit compatibility policy. Native and browser must use the same codec, with native-file and awaited IndexedDB adapters. Retain the existing prohibition on localStorage/sessionStorage.

## Timing and spatial parity

At source baseline walk137.5px/s and passive shakes0.8/s, fresh20→100 is a100s runway. Mandatory route/campaign legs have a60s budget; coverage to a **potentially** legal smoke spot has a45s budget. Conditions are ignored only for the coverage measurement, not actual smoking legality. Source `tools/world-gate.mjs` explicitly measures straight-line lower bounds, not collision-aware paths.

If keeping the current 3D base walk3.6m/s, a neutral initial scale is **3.6/137.5 =0.0261818m per source pixel**. The full source rectangle then spans about225.16m ×146.62m;60s and45s correspond to216m and162m at baseline walk. This is a starting conversion, not a finalized level layout. Tall meshes, fences, doors, stairs and detours must not make the previously legal paths too slow. Preserve site relationships and compare measured path times after geometry exists. Do not scale melee, body dimensions or UI offsets blindly using this world factor.

Routes retain three distinct stops, early/late unlock filters, previous-final-stop exclusion, partner-floor and co-routability checks, plus the named excluded `scrap_gate ↔ ditch_gauge` pair unless a new geometry/spec decision supersedes it. Compare source and 3D legality graphs rather than copying an old pixel constant into a metre-based generator. The nearest-legal-smoke objective must use the same legality function as the actual smoke action.

## Discrepancies to resolve explicitly

These are audit observations, not authorization to fix unrelated 2D source. Keep an exception ledger for each deliberate port correction with original behavior, selected 3D behavior and a counterexample test.

1. `combat.js:die` leaves current high/crash timers; slice `simulation.gd:hurt` clears them. Source fresh brain70/dayTime0.35 differs from slice brain100/dayTime0. Slice deterministic withdrawal/melee, Lurch stats and daily rewards are reduced-slice decisions, not v22 baseline parity.
2. Source death preserves cash/rocks/items. Arrest takes70% cash and all real rocks, not all inventory. Older hideout prose that says both death/arrest zero cash/rocks disagrees with `die/arrestScene`.
3. `combat.js:onNpcDeath` uses bare `cashPiles.push` for Brendan despite importing `runtime`, not a `cashPiles` binding. Static inspection indicates a ReferenceError on that branch. The weapon-drop condition `n.id === 'larry' && !P.weapon || P.weapon === 'fists'` also awards a pipe on any ordinary fists kill due to operator precedence. These need characterized bug cases, not blind translation.
4. Most normal world time pauses in menus, but day7 silence uses `Date.now`, and several delayed events use `setTimeout` (radio reinforcements, ally/event presentation and delayed endings). Native simulation scheduling must explicitly distinguish these; converting all timers into paused game time changes behavior.
5. Sleeping and natural dawn are not one shared source function: sleep calls counter/weather/hustle/day-event updates, while natural dawn additionally handles rent, free bus pass, proud calls and garbage truck. Do not silently normalize these differences without a decision.
6. `smokeRockAt` is an effect function; caller guards currently carry resource/high/venue checks. The full action boundary should consolidate validation while preserving legal outcomes. `concessionMenu` already rechecks condition at action time. Preserve a single smoke effect implementation.
7. Stripe ordinary soap is an inventory item; heat's `soaprock` outcome populates `P.soapRocks` consumed before real rocks. The ordinary cook soap byproduct is also an item. Conflating these changes inventory, heists, fencing and intro behavior.
