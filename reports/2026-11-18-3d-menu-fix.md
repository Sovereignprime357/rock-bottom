# Browser menu-loop fix — 2026-11-18

Branch: `codex/3d-browser-menu-fix`. Decision register: `IMPL-3D-INPUT-01` in
`../REFACTOR-FINDINGS.md`. Scope: the separate Godot slice; original 2D runtime and frozen v19
are untouched.

## Result

Reproduced the operator's Continue→pause loop in the local in-app browser. Godot's Web
mouse-mode getter observes actual pointer lock while its setter only requests it. The next
physics tick incorrectly treated a pending/refused request as a reason to pause. The original
Escape toggle could also resume immediately after browser unlock had already paused.

Resume now enters play while capture is pending or refused. Only losing a lock actually
observed during that play session pauses. Web Escape is pause-only; deliberate Continue and
conversation exits resume. Right-drag look and left-click combat work without lock. Focus loss
still pauses, and a late grant cannot keep the cursor trapped in a modal.

Normal reload initially retained the broken cached `index.pck`: server logs showed only an HTML
request and the pause control copy was still old. The build now emits a SHA-256-named pack and
updates `mainPack` plus the progress-size key. A subsequent normal reload fetched that new pack.
Engine files, storage namespace and save schema remain unchanged.
