# Full-world weather presentation — P14d

Status: approved bounded presentation packet. `FullScene` integration and all engine runs belong to the root worker. This does not change the slice or claim whole-scene 60-actor performance acceptance.

## Source authority

- `src/render/landmarks_a.js:368` owns `nightAmount`: night is 1 for `t < .2` or `t >= .8`; dawn is `1-(t-.2)/.1` for `.2 <= t < .3`; day is 0 for `.3 <= t < .7`; dusk is `(t-.7)/.1` otherwise. In particular `.65` is fully daytime. No sinusoid, phase wrap, or separate day clock replaces this equation.
- `src/render/actors_weather.js:113` draws exactly 160 deterministic rain lines using `performance.now()/30`, `(i*73+t)%W`, `(i*47+t*1.4)%H`, ending at `x-3,y+10`. Fog uses `.72-nightAmount()*.18`, then restores alpha. Source clear draws neither effect. These calls consume no gameplay RNG or mutate player/state.
- `src/render/frame.js:26,259` uses wall render time and draws weather after world lighting. Menu pauses do not stop this cosmetic wall time. `src/core/update.js:895` uses the same dawn/day/dusk/night boundaries for the HUD.
- Gameplay `isNight()` (`src/data/npc_spawns.js:45`) deliberately uses `t < .25 || t > .75`, a different predicate from rendered night amount. Actor visibility/gameplay gates remain with their existing model owners; the presenter must never feed its lighting factor back into those decisions.
- `src/render/landmarks_a.js:258` gates 11 source lamp posts and 24 `WORLD_LIGHTS` by night amount greater than `.01`; the office fixture also requires `office.upgrades.generator`. Four burn barrels use `max(.30,nightAmount)`. Static fixture colors and individual powers remain distinct. Dynamic cop/pipe emitters are outside this packet; it does not add moving lights to the actor roster.
- `DaySystem` already rolls and persists clear/rain/fog (65%/23%/12%). Source update particles are cosmetic and are not copied into a second RNG-consuming particle system. No source lightning/thunder timer exists; this packet adds none.

## API and ownership

New `FullWeatherPresentation` (`weather_presentation.gd`, `Node3D`):

- `build(world: Node3D, camera: Camera3D) -> bool`: once, bind a built full world, its existing environment/sky/sun, the 39 existing static lights, and allocate one 160-instance rain MultiMesh. Reject a slice or incomplete bindings before changing lights.
- `sync(snapshot: Dictionary, visual_ms: float) -> bool`: required fields `{dayTime: finite number in [0,1], weather: clear|rain|fog, office_generator: bool, geometry_revision: nonnegative integer}`. Read-only detached input. `visual_ms` is the caller's already available `Time.get_ticks_msec()` wall render timestamp. Invalid input refuses before presentation mutation.
- `clear()`: hide all rain, discard coverage certificates, invalidate presentation caches; next valid sync reapplies current authoritative state. No player/state ownership, timers, RNG, physics bodies, persisted fields, or events.
- `inspect() -> Dictionary`: detached counters/profile/instance evidence, including query count per sync and coverage revision. `night_amount(t)` and `fog_opacity(t)` are pure source equations. `source_rain_line(index,visual_ms)` is a pure reference helper for the independently captured source rain formula; original 3D spatial placement is explicitly separate.

Root keeps one strong `weather_view`, calls `build` after world/camera exist, replaces only full-scene `world.set_day_time(s.dayTime*240)` with `weather_view.sync`, and supplies the authoritative adapter `_collision_revision`. The generator boolean comes from `runtime.s.office.upgrades.generator`. It clears presentation on epoch reset. `neighborhood.gd`, the slice, model time, gameplay night gates, and Day weather rolls stay unchanged.

## Approved spatial and visual adaptations

The screen overlay becomes one depth-tested opaque MultiMesh with 160 original narrow two-triangle slate streaks (320 triangles, one surface/draw submission). There are no per-drop nodes, simulation particles, shaders, audio, transparent sorting, or collision objects. Sixteen world-grid columns carry ten phase-offset streaks each in a camera-centered 10 m square. Time derives directly from the supplied wall timestamp; deterministic index arithmetic replaces cosmetic randomness. No incremental simulation clock accumulates drift.

For first-person roofs, each fixed column obtains a cached downward layer-1 ray from above the world's roofs to below ground. Drops beneath the highest cover at that exact column are hidden, including a streak-length clearance. This is a visual center-line certificate, not a claim that thin angled rain quads have full swept collision. Columns change only at a 2.5 m camera grid crossing or geometry revision. At most four uncertified columns are queried per `sync`; uncertified columns stay hidden. Reused columns retain certificates only for the same revision. Stationary certified rain does zero physics queries. Cover rays exclude actors/player, and neither their result nor rain modifies world collision or navigation. All caches are bounded by 16 columns.

Collision-revision publication can precede the PhysicsServer synchronization of a cart/prop transform in the same process frame. A new revision therefore invalidates and hides all columns immediately, records the current engine physics-frame serial, and begins certification only after that serial advances. Same-revision camera regrids can reuse/query immediately. This is a physics validity fence, not an additional gameplay or weather clock. The gate publishes an actual new roof and revision in the same frame, proves no stale-pose certification occurs, then proves its real roof height is discovered after physics synchronization.

Source night amount drives the existing sky/sun/ambient resources, retaining the accepted dirty slate/cream palette and readable night ambient floor. Existing individual native fixture powers are preserved: street posts `.55`, source fixture declared `power`, barrels `.9`; energy is baseline times source activation level. The office generator never illuminates before purchase. No new lights or shadows are allocated. Mesh lens colors remain their existing authored materials; this packet controls actual light energy, not batched material extraction.

Ordinary Compatibility environment fog replaces the 2D fog sheet. Clear haze density is `.0028`; rain haze is `.0055`; fog density is `.0028 + .026*(.72-.18*night)`. The reduced night fog follows the source readability rule. Source weather changes have no tween timer: clear/rain/fog transition immediately on the next valid sync. Sun/ambient/sky color mapping is an explicit 3D presentation calibration, not a claim of identical Canvas compositing. Sky/profile writes occur at most four times per wall second during ordinary dawn/dusk changes, and never on unchanged plateaus; weather/generator/revision-independent epoch reset or large time jumps apply immediately. Rain transforms update once per supplied visual timestamp and camera/coverage change.

The first headless gate exposed an engine-test limitation: pinned [Godot4.5.1 dummy mesh storage](https://github.com/godotengine/godot/blob/4.5.1-stable/servers/rendering/dummy/storage/mesh_storage.h#L154) returns identity unconditionally for the per-instance transform getter, although it stores the submitted bulk buffer. Headless geometry assertions therefore decode the actual read-back `MultiMesh.buffer` using the pinned [GLES3 row layout](https://github.com/godotengine/godot/blob/4.5.1-stable/drivers/gles3/storage/mesh_storage.cpp#L1565). They retain all hidden-column and transformed-vertex roof checks. The native probe separately requires the real renderer getter to match all160 submitted transforms, checks hidden instances and every visible mesh vertex against its certified cover and declared render bounds. No production geometry or query volume is changed to make that test pass. JSON fixture counts are compared as integers and against actual array lengths, rather than type-strict dictionary equality with JSON floating-point values.
