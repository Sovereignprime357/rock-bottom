2026-11-19. Spec before code. Root ratified the selected Windows first-person and
keyboard/mouse Web targets and the exact30 classifications in the held
`reports/3d-parity-metadata/handler-dispositions.json`. This system implements metadata and validation only. It changes no gameplay,

  authoring, retaining identity, palette, finite geometry, grounding and caching.

  explicit canonical toolkit edges. Aliases cannot invent tests or platforms.

  retains both1280x720 and960x540 and excludes only touch-topbar accommodation.
- `init_frame` is a source-proven empty exported initializer. Its no-op decision
  never discharges `drawAll`, which retains the aggregate observable renderer
  obligations and explicit unresolved implementation/platform evidence.

These decisions are orthogonal to the current585 handler and32 feature rows.
The baseline's555 integrated/28 partial/2 planned handler statuses and all feature
statuses remain byte-equivalent as parsed JSON. No new excluded/verified status,
terminal completion state, evidence-array promotion or implied full-port percentage
is introduced. Root's approval applies to this exact scope, not a generic exemption.

## Artifact/API

`tools/parity-metadata-migrate.mjs` reads pinned production/source and the held proposal/index, then
uses explicit `--write` to regenerate `game3d/data/parity_manifest.json`; its default is check-only. It adds a top-level
`scopeMetadata`,30 handler `disposition` objects and32 feature `evidenceRefs`/
`coverageBoundary` objects. The96 references retain their feature, selected
target, qualification, precise coverage and limitations; references to the same
artifact are not96 independent tests. Original nativeEvidence/webEvidence lists
remain unchanged. A deterministic `--check` compares generated bytes without writing.

`tools/parity-metadata-gate.mjs` checks the additive manifest. `--complete` retains the original
requirement that every handler/feature is verified with both platform evidence
lists; it must still fail. Metadata can never satisfy those existing lists.
The reusable validator returns structured errors/check counts for focused tests.
Only an explicitly requested reviewed migration writes the live manifest. The existing production parity gate remains unchanged.

## Validation contract

Pin the complete input manifest, source content/corpus, inventory matrix, proposal,
evidence index, decision spec and every referenced implementation/test/spec/source
file. Resolve paths within the real workspace, reject absolute/traversing/escaping
references, and compare actual file bytes. Any changed referenced source invalidates
the draft until an explicit reviewed rebase; regeneration cannot silently repin it.

Strip only the newly allowed fields and require exact structural equality to the
pinned baseline. Check585/32 unique IDs independently against exported function
omissions and the inventory matrix. Require the exact30 disposition identities,
classes and target lists. Check the nine actual import/export binding statements,
matching canonical exported function names and a cycle-free relation. Reexport
proofs are source- and symbol-specific; makeRoutePatch cannot be substituted.
For the empty initializer, independently require its actual exported zero-argument
function body to contain no executable token. Both its file hash and lexical body
proof must pass. Mixed/aggregate retained obligations cannot be removed or broadened
into a blanket target exclusion.

Each evidence reference has a pinned artifact, exact scenario/target qualification,
fixture disclosure, provenance/review boundary and inspected outcome selectors.
JSON selectors must resolve actual fields, including finite array selectors; typed
outcome values are compared, not coerced. Report/log evidence uses exact real
sections or marker lines and excerpt hashes. PNG evidence is only a hashed rendered
artifact with no machine outcome or automatic visual acceptance. Supporting reports,
packaging, failed profiles and staged visual fixtures remain their distinct classes.
Web/native report identity is validated against its pinned scenario rules; a native
run cannot enter a Web slot by relabeling. Explicit `visual_acceptance:false` stays
false; any human review remains a separately attributed report, never synthesized.
All references are `index_only`, never full-feature acceptance; remaining native/Web
obligations stay visible on each feature.

The ledger is a trustworthy index, not an automated judge of comedy, audio or human
visual review. Successful validation establishes preserved census, source mapping
and exact evidence attribution. It does not pass native/Web gameplay,90-second
bosses,16ms/60+NPC performance, or repository delivery.

wrong/cyclic alias, nonempty init_frame even with a locally updated file hash,

screenshot replacing all96 references, invented human review and dropped remaining
coverage. Verify deterministic migration and expected failing --complete. Tests use
detached data/read overrides only and never modify source or retained evidence.

# Executable declaration proof correction

2026-11-19, spec before correction. Peer review showed two false positives in the
independent source proof: import/export text entirely inside comments passed the
alias check, and a regular-expression literal containing an initializer declaration
passed the empty-body check. The actual pinned source remains valid. Retain both
exact counterexamples; do not change the585/32 obligations, metadata, evidence or
explicit v2 input pins.

Replace regex searches over source text with a bounded lexical scan. Comments are
discarded; strings, regular expressions and complete templates (including nested
interpolations) become opaque tokens. Balanced executable delimiters establish
top-level module scope. Only top-level named imports/local exports and exported
function declarations may prove an alias; canonical function names must match.
An empty initializer must have exactly the executable token sequence of a zero-
argument function with an immediately closing body, after comments are removed.
String/directive expressions, semicolons and blocks remain executable tokens.

Slash classification follows expression-end versus expression-start context and
tracks control-statement parentheses. Ambiguous slash after a closing brace,
unsupported tokens or malformed/unclosed lexical constructs reject the proof.
This is a conservative scanner for the pinned active modules, not a complete
JavaScript parser and not a source executor. False refusal requires an explicit
future scanner extension; uncertainty must never fabricate a declaration.

Verify the actual nine aliases and actual empty initializer, comment-only bodies,
division in the real modules, both reported false positives, line/block comments,
ordinary strings, nested template/interpolation text, regex escapes/classes,
control-parenthesis regex contexts, nested declarations and malformed constructs.
All previous hash, target, outcome, census and expected-completion checks still run.
